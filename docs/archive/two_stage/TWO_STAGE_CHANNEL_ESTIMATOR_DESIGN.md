# TwoStage 第一阶段：可验证的有向物理损害估计

## 1. 为什么现在不改第二阶段

oracle PhysicalNegotiation-v2 在测试集上达到 threshold MWS 0.657、sampled 0.664；打乱队列后真实效用下降约 34%。这已经证明第二阶段能够把准确的信道量与 Q 结合成有效、队列敏感的集合。

因此下一项只回答：分布式信道 GAT 能否提供足够准确的物理量？如果同时改变第二阶段，就无法知道部署性能下降来自哪里。

## 2. 第一阶段到底需要输出什么

### 2.1 单链路收益不需要 learning

仿真中节点输入是本链路 SNR(dB)，而单独发送速率为

```text
b_i = log2(1 + 10^(SNR_i/10) / Gamma),
```

其中 `Gamma` 是 SNR gap。测试数据上公式得到的 oracle `b_i` 与 SNR 相关系数为 0.9997。让 MLP重新学习已知公式不会增加有意义的灵活性，只会引入误差，因此直接计算。

### 2.2 有向损害需要 learning

目标仍为

```text
rho_(i->j) = [R_j({j}) - R_j({i,j})] / R_j({j}).
```

当前归一化 edge weight 与该目标的简单线性相关为 -0.398，说明它不能直接替代速率损害。其原因可能包括逐图归一化、特殊拓扑冲突边，以及有效损害同时依赖受害链路自己的信号质量。

因此每条边使用共享 MLP：

```text
rho_hat_(i->j) = sigmoid(
    MLP_edge(h_i, h_j, w_(i->j))
).
```

- `h_i`：冻结会议版信道 GAT 对干扰者链路的表示；
- `h_j`：受害者链路的表示；
- `w_(i->j)`：该有向边的直接干扰特征；
- sigmoid：目标本身是 0 到 1 的损失比例，因此输出范围约束来自物理定义。

MLP 不接收 Q、教师动作、基础 GAT 的调度分数 `c_i` 或额外 SNR bypass。SNR 已经是基础 GAT 的输入，并且 `b_i` 由物理公式单独处理。

## 3. 为什么先冻结基础 GAT

冻结是指训练边损害头时不更新会议版 GAT 参数。这样第一项实验只检验会议版信道表示是否已经包含估计有向损害所需的信息。

若失败，下一项才单独解冻或重新训练第一阶段；不能一开始同时更新全部模块，否则无法区分“原表示不足”和“边头设计不足”。

## 4. 训练和评价

训练损失是预测 `rho_hat` 与精确物理 `rho` 的均方误差（MSE）：先计算每条边误差的平方，再平均。MSE 不涉及调度教师。

单独报告：

- MAE：平均绝对误差，直观表示损害比例平均差多少；
- RMSE：均方根误差，对大误差更敏感；
- Pearson correlation：预测和真实损害是否随边共同变化；
- prediction mean/std：检查是否只输出一个常数均值。

然后冻结该估计器和已经训练好的协商器，用预测 `rho_hat` 替换 oracle `rho`，完整重复 MWS、队列打乱和分密度测试。

判别逻辑：

- 预测误差小且调度接近 oracle：第一阶段可行，进入多 seed 和动态队列实验；
- 预测误差大且调度明显下降：先修正信道表示，不改第二阶段；
- 预测误差看似小但调度下降大：说明协商器对特定关键边误差敏感，需要按调度后果分析误差，而不是只看平均指标。

## 5. 实验 3A：冻结 GAT 的有向损害回归

### 设置

200/32/32 个信道图，15 epoch，seed=42。冻结会议版 GAT，仅训练 3,169 个边头参数。原始报告：`results/diagnostics/physical_channel_estimator_20260712_020741.json`。

### 物理量预测结果

测试 MAE=0.214、RMSE=0.284、相关系数=0.431。预测均值 0.720 接近真实 0.707，但预测标准差仅 0.096，显著小于真实 0.311。

这说明模型不是只输出严格常数，但明显把极强/极弱损害向均值压缩。冻结的会议版表示足以恢复一部分有向损害排序，却没有完整保留极端损害幅度。

### 接入冻结协商器后的静态调度

| 输入信道量 | 总体 | 稀疏 | 中等 | 密集 |
|---|---:|---:|---:|---:|
| oracle `rho` | 0.657 | 0.743 | 0.683 | 0.609 |
| predicted `rho` | 0.627 | 0.722 | 0.660 | 0.571 |

预测版本平均激活 1.22 条，precision/recall/F1=0.752/0.451/0.564。打乱队列后效用只剩正常策略的 64.1%，与 oracle 的 66.0%接近。

### 结论

虽然平均 `rho` 回归误差不小，完整调度只下降约 3 个百分点，说明协商器对多数边的幅度误差较鲁棒；密集场景下降约 3.8 个百分点，符合“极端损害压缩在密集竞争中更重要”的解释。

第一阶段 H3 暂时通过，可以进入多时隙队列测试。但在最终模型定稿前仍需比较：解冻/重训信道 GAT 能否提高极端损害预测，以及这种提高是否真正改善动态 QoS；不能只为更好 RMSE 增加训练复杂度。

## 6. 重新审计后，H3 被否定：不是网络容量，而是输入不可辨识

### 6.1 为什么重新打开这个问题

Anchor-Exact-OneJoin 使用 predicted `rho` 时静态为 0.719，但动态中高负载明显落后；换成 oracle `rho` 后，动态 λ=2/5/10 分别从 0.733/0.339/0.191 提高到 0.943/0.560/0.307。第二阶段结构不变，差异只能来自第一阶段。

因此，前文“完整调度只下降 3 个百分点，所以 H3 暂时通过”的判断只适用于当时保守、低并发的 v2 解码器。允许条件加入后，极端干扰压缩会直接产生错误并发，H3 必须重新审计。

### 6.2 当前 edge weight 丢失了什么

原始有向冲突权重为

```text
w_raw(i->j) = I_(i->j) / (S_j / beta - N),
```

随后代码对每张图单独执行

```text
w = log10(1 + w_raw) / max_edge log10(1 + w_raw).
```

最后一步保留了图内相对顺序，却删除了跨图绝对尺度。归一化后的 `0.5` 只表示“当前图最大边的一半左右”，不能唯一决定真实 `I/N`。这叫不可辨识：多个不同物理状态会映射到同一个模型输入，任何容量的 GAT 都不可能从该输入唯一恢复原状态。

诊断 `experiments/diagnose_analytic_rho.py` 强行假设每图最大原始权重都是 `1e5`，结果 MAE=0.214、RMSE=0.402、相关系数=-0.057，预测均值高达 0.917。失败说明逐图归一化不能可靠逆转。

### 6.3 物理充分量：SNR 与 INR

INR（interference-to-noise ratio）定义为某干扰发射端在受害接收机处的干扰功率与噪声功率之比：

```text
INR_(i->j) = I_(i->j) / N.
```

它是接收端局部可测量量，不是中央调度器才能获得的全局标签。给定受害链路 `SNR_j` 和该边 `INR_(i->j)`，两链路并发时的速率可由已知物理公式直接计算：

```text
R_j({i,j}) = log2(1 + SNR_j / ((1 + INR_(i->j)) Gamma)).
```

诊断 `experiments/diagnose_physical_rho_sufficiency.py` 对 164,437 条有向边验证：由 SNR/INR 恢复 oracle `rho` 的 MAE=0、RMSE=0、相关系数=1。共享端点边和普通边都严格成立。

### 6.4 新结论

第一阶段不应继续用更大 MLP 猜测被归一化删除的尺度。下一版输入必须保留：

1. 每条链路的绝对 SNR；
2. 每个有向候选干扰对的绝对 INR，采用固定单位或固定变换，不能逐图除以最大值；
3. 对多链路集合，INR 必须可相加，因为受害接收机的总干扰为各活动干扰源 INR 之和。

GAT 的职责不是重新拟合 Shannon 公式，而是聚合这些充分物理量，理解“当前候选会影响谁、谁又会影响未来候选”的网络结构。
