# 问题解答

## 问题1：为什么模型会突然从 π_mean≈0.1 突变到 π_mean=1.0？

### 根本原因：损失函数的竞争关系失衡 + Softmax 饱和

#### 1. **损失函数的竞争关系**

你的损失函数是：
```
L = -Σ(Q * rates) + λ·mean(π) + μ·Σ w_ij·π_i·π_j - τ·entropy
```

**各项的作用**：
- `-Σ(Q * rates)`：**鼓励激活链路**（因为激活链路能获得速率，这个值可能很大，如 100+）
- `μ·Σ w_ij·π_i·π_j`：**惩罚冲突链路同时激活**（只有当 π 接近 1 时才显著）
- `λ·mean(π)`：**稀疏性惩罚**（相对较小，如 0.2 * 0.1 = 0.02）
- `-τ·entropy`：**熵正则化**（防止极端分布）

**突变过程**：
1. 模型学习到"激活更多链路能获得更高速率"
2. `-Σ(Q * rates)` 的梯度**持续推动所有 π 向 1 移动**
3. 虽然 `conflict_penalty` 会增大，但**只有当 π 接近 1 时才会显著**（二次项 π_i·π_j）
4. 如果某个 batch 的速率收益特别大，可能会**一次性抵消所有惩罚项**

#### 2. **Softmax 的饱和特性**

**Softmax 的问题**：
- 当 logits = [-5, 5] 时，softmax 输出 ≈ [0, 1]
- 当 logits = [-10, 10] 时，softmax 输出 ≈ [0, 1]（几乎相同）
- **梯度消失**：一旦进入饱和区，即使 loss 很大，梯度也接近 0，无法回退

**突变过程**：
1. 某个 batch 的梯度特别大（或学习率累积效应）
2. logits 第二类从 [0, 2] 跳到 [5, 10]
3. softmax 输出从 [0.5, 0.5] 跳到 [0.01, 0.99]
4. **梯度消失**，模型无法回退，陷入"全激活"状态

#### 3. **学习率和梯度累积**

- **学习率 LR = 0.001**（相对较大）
- **Adam 优化器**：会累积历史梯度，如果某个方向持续有梯度，会加速更新
- **梯度裁剪 max_norm=0.5**：虽然限制了单次更新，但如果多个 batch 方向一致，累积效应仍可能导致突变

#### 4. **冲突惩罚的滞后性**

从代码看：
```python
conflict_penalty = Σ w_ij * π_i * π_j * penalty_scale
```

**问题**：
- 当 π 在 [0, 0.5] 时，惩罚项很小（π_i·π_j ≤ 0.25）
- 只有当 π 接近 1 时，惩罚项才会显著（π_i·π_j ≈ 1）
- **惩罚是滞后的**，无法在早期阻止模型向"全激活"方向移动

### 为什么前面几乎 π_mean 都在 0.1 左右？

因为：
1. **稀疏性惩罚** `λ·mean(π)` 在起作用（虽然小，但持续）
2. **冲突惩罚** 在 π 小时虽然小，但也在起作用
3. **熵正则化** 在推动 π 向中间值移动
4. **Softmax 的竞争机制**：如果所有链路的 logits 都接近，softmax 会输出接近 0.5 的概率，但稀疏性惩罚会推动它向 0 移动

### 为什么会突变？

**触发条件**：
1. 某个 batch 的速率收益特别大（可能是网络拓扑特别有利）
2. 梯度累积：多个 batch 的梯度方向一致，累积效应导致 logits 跳到极端值
3. **Softmax 饱和**：一旦 logits 第二类稍微大于第一类，softmax 就会输出接近 1 的概率，然后梯度消失，无法回退

## 问题2：不用 softmax，改成正常输出会好一些吗？

### 答案：**是的，用 sigmoid 会更好！**

我已经在代码中实现了 sigmoid 替代 softmax 的方案。

### Sigmoid vs Softmax 对比

| 特性 | Softmax | Sigmoid |
|------|---------|---------|
| **输出范围** | [0, 1]，且每行和为 1 | [0, 1]，每个值独立 |
| **竞争机制** | ✅ 有（归一化导致竞争） | ❌ 无（每个链路独立） |
| **梯度稳定性** | ❌ 容易饱和，梯度消失 | ✅ 更稳定，梯度在 [-3, 3] 范围内都有效 |
| **饱和问题** | ❌ 一旦进入饱和区无法回退 | ✅ 即使接近边界，仍有梯度 |
| **适用场景** | 多分类（需要竞争） | 二分类/独立决策 |

### 为什么 Sigmoid 更适合你的场景？

1. **独立决策**：每个链路的激活是独立的，不需要"竞争"
2. **梯度稳定**：sigmoid 的梯度在 [-3, 3] 范围内都有效，不会突然消失
3. **避免饱和**：即使接近边界（如 0.99），仍有梯度，可以回退
4. **更灵活**：可以同时激活多个链路，不需要归一化

### 使用 Sigmoid 需要注意什么？

1. **需要更强的稀疏性惩罚**：因为失去了 softmax 的竞争机制，需要 `lambda_sparsity` 更大
2. **需要更强的冲突惩罚**：因为每个链路独立决策，冲突惩罚需要更激进
3. **初始化调整**：初始概率应该接近 0.1-0.2（而不是 0.5），通过初始化 bias 实现

### 我已经实现的改进

1. **改用 Sigmoid**：`final_scheduler` 输出单个分数，然后用 `sigmoid(score / temperature)` 映射到 [0, 1]
2. **温度缩放**：训练时用较大温度（2.0），让分布更平缓；评估时用较小温度（1.0），让决策更清晰
3. **初始化调整**：bias 初始化为 -2.0，让初始概率在 0.12 左右
4. **增强监控**：添加了更详细的梯度、损失、冲突惩罚监控，帮助诊断问题

   - `grad_norm`：应该在 0.01~1.0 范围内
   - `π_mean`：应该在 0.1~0.4 范围内
   - `conflict_penalty`：应该与 `rates_sum` 平衡
